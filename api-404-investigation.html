🚨 ROOT CAUSE IDENTIFIED

The frontend's getAnalytics() function in lib/api.ts calls:

export async function getAnalytics(projectId: string) { const project = await getProject(projectId) as any const tasks = await getTasks(projectId) const events = await getProjectEvents(projectId) ← THIS CALLS /events (404) const members = project.members?.map((m: any) => m.user) || [] return computeAnalytics(tasks, events, members) }

getProjectEvents() tries to fetch from /api/projects/${projectId}/events which does not exist.

Analytics endpoint works fine, but frontend logic fails trying to fetch events separately.

🔧 FIX APPLIED

Updated lib/api.ts getAnalytics() function to:

export async function getAnalytics(projectId: string) { try { // Direct call to analytics endpoint - it already computes everything server-side const response = await fetchJson(`/api/projects/${projectId}/analytics`) return response } catch (error) { // Fallback if analytics endpoint fails const project = await getProject(projectId) as any const tasks = await getTasks(projectId) const members = project.members?.map((m: any) => m.user) || [] // Use empty events array since /events endpoint doesn't exist const events: any[] = [] return computeAnalytics(tasks, events, members) } }

Key Changes:

  • Directly calls working /api/projects/[id]/analytics endpoint
  • Adds fallback with empty events array
  • Uses server-side computation (which already works)
  • Maintains backward compatibility
