Critical Bugs Found and Fixed

Bug #1: PATCH /api/tasks/[id] - Broken completedAt Logic

File: app/api/tasks/[id]/route.ts:51

Problem: The condition checked status === 'done' twice with ternary logic error:

completedAt: status === 'done' ? new Date() : status === 'done' ? undefined : null

Impact: FAIL - When editing only a task's title while it's Done, completedAt was incorrectly cleared.

Fix #1: Corrected completedAt Logic

Updated to properly handle status changes:

completedAt: status ? (status === 'done' ? now : null) : undefined

Result: PASS - Title-only edits don't affect completedAt. Status changes properly set or clear it.

Bug #2: PATCH /api/tasks/[id] - Missing Transition Validation

File: app/api/tasks/[id]/route.ts

Problem: PATCH endpoint allowed direct status changes without validating transitions.

Impact: FAIL - List view dropdown could bypass required workflow (Backlog→In Progress→Review→Done).

Fix #2: Added Transition Validation to PATCH

Added same ALLOWED_TRANSITIONS validation as move endpoint:

if (status && status !== oldTask.status) { const allowedTo = ALLOWED_TRANSITIONS[oldTask.status] || [] if (!allowedTo.includes(status)) { return NextResponse.json({error, allowed}, {status: 422}) } }

Result: PASS - Both board drag and list dropdown enforce identical rules.

Bug #3: PATCH /api/tasks/[id] - Incorrect TaskEvent.fromStatus

File: app/api/tasks/[id]/route.ts:56

Problem: oldTask was fetched AFTER the update, so it contained the NEW status.

Impact: FAIL - Burndown chart history corrupted due to wrong fromStatus in TaskEvent.

Fix #3: Fetch oldTask Before Update

Moved findUnique call before the update:

// Get current task state BEFORE update const oldTask = await prisma.task.findUnique({where: {id}}) if (!oldTask) return ... // Then update const task = await prisma.task.update({...})

Result: PASS - fromStatus correctly records old state for accurate burndown replay.

Bug #4: Analytics Burndown - Unsorted Events

File: app/api/projects/[id]/analytics/route.ts:33-38

Problem: Events were replayed in database order, not chronological order.

Impact: FAIL - Burndown calculations incorrect when events arrive out of order.

Fix #4: Sort Events Before Replay

Added event sorting:

const sortedEvents = events.sort((a, b) => new Date(a.createdAt).getTime() - new Date(b.createdAt).getTime() ) for (const event of sortedEvents) { // replay task transitions }

Result: PASS - Burndown accurately reflects task history in temporal order.

Bug #5: Task Move - Incomplete completedAt Clearing

File: app/api/tasks/[id]/move/route.ts:49

Problem: When moving from done, completedAt was set to undefined (don't change) instead of null (clear).

Impact: FAIL - Moving done→in_progress left completedAt set.

Fix #5: Always Clear completedAt When Moving Away from Done

Updated completedAt logic:

completedAt: toStatus === 'done' ? now : null

Result: PASS - completedAt is set only when task reaches Done; cleared for any other status.
